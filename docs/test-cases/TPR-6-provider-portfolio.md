# Dokumen Test Case: Pengelolaan Portofolio Penyedia Jasa (`TPR-6` / `PBI-06`)

- **PBI Key**: `TPR-6` (PBI-06: Portofolio Penyedia Jasa)
- **Subtask Penyusunan Test Case**: `TPR-130` (Menyusun test case pengelolaan portofolio penyedia jasa)
- **Subtask Pengujian Eksekusi**: `TPR-48` (Menguji pengelolaan portofolio)
- **PIC / Penyusun**: Muhammad Naufal Sinambela
- **Lingkup Modul**:
  - Frontend Penyedia Jasa: `/provider/dashboard/portfolio` (`PortfolioManagementClient`, `PortfolioCard`, `PortfolioFormModal`, `DeletePortfolioDialog`, `usePortfolio`) dan menu sidebar "Portofolio"
  - Frontend Publik: `/preview/providers/[id]/portfolio` (`PublicPortfolioPreviewClient`, `PublicPortfolioGallery`, `PortfolioLightbox`)
  - Backend REST API: `GET /api/providers/:id/portfolio`, `GET /api/providers/me/portfolio`, `POST /api/providers/me/portfolio/upload-url`, `POST /api/providers/me/portfolio`, `PATCH /api/providers/me/portfolio/:id`, `DELETE /api/providers/me/portfolio/:id`
  - Database: Tabel `public.provider_portfolios` (Foreign Key `provider_id -> public.profiles(id) ON DELETE CASCADE`, check judul/deskripsi, constraint `provider_portfolios_image_path_format`, unique index `image_path`), fungsi `public.is_public_provider(uuid)` (`security definer`), dan RLS per peran
  - Storage: Bucket `portfolio` (publik baca, `file_size_limit = 5242880`, `allowed_mime_types = {image/jpeg,image/png}`) dan storage policy per folder `{auth.uid()}/`

## 3. Ringkasan Hasil Eksekusi Pengujian (`TPR-48`)

- **Tanggal Eksekusi**: _diisi setelah eksekusi_
- **File Pengujian Otomatis**: `backend/src/tests/portfolio.test.ts` (disusun di `TPR-48`)
- **Perintah**: `cd backend && npm run test:tpr48` (khusus `TPR-48`), `npm run test:tpr130` (struktur dokumen ini), atau `npm test` (seluruh suite)
- **Metode**:
  - Backend: pengujian integrasi router Express (`createPortfolioRouter`) dengan middleware autentikasi tiruan (Penyedia A, Penyedia B, customer, tamu) dan store database + storage in-memory yang meniru aturan RLS dan storage policy, menggantikan Supabase melalui `setPortfolioStoreForTesting`. Kegagalan storage (`TC-PF-14`, `TC-PF-23`) disimulasikan lewat store tiruan.
  - Database & storage: query per peran di SQL Editor Supabase pribadi (`TC-PF-16`, `TC-PF-28`) dan unggahan langsung ke signed URL dari browser (`TC-PF-19`), karena tes mock tidak menangkap masalah izin database maupun konfigurasi bucket.
  - UI: dibuktikan lewat screenshot (`TC-PF-03`, `TC-PF-08`, `TC-PF-12`, `TC-PF-24`, `TC-PF-31`, serta bagian UI pada `TC-PF-05` s.d. `TC-PF-07`, `TC-PF-13`, `TC-PF-14`).
